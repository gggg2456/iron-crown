# 铁与王冠 · Iron & Crown

> 中世纪「红色警戒」风格的即时战略：采集金矿、重建兵营、让长矛与弩矢重新列阵，从黑鸦公国的铁蹄下夺回被踏碎的故土。
> 纯前端 Canvas 2D 手绘等距战场，零外部依赖、离线可玩，由 Electron 打包为 Windows 独立版。

```
  赤蔷薇最后的血脉回来了 —— 身后只有三名农民、几队残兵，和一面褪色的旗。
```

## v1.9.0 地形战术：高地 / 沼泽 / 灰烬 / 王座

### 数值

| 地形 | 效果 | 实现位置 |
| --- | --- | --- |
| 高地 `highland` | 远程单位与箭塔/弩炮塔射程 **+1** | `updateUnit` 射程、建筑 `bRange` |
| 沼泽 `marsh` | 轻装移速 **×0.8**，重甲（骑士/冲车/攻城车/基地车）**×0.6** | `terrainSpeedAt()` |
| 灰烬 `ash` | 站在灰烬上的攻击者伤害 **×1.1**；自身每秒 **-1 生命**，保底 1 点 | `damage()` / `updateTerrain()` |
| 王座 `throne` | 占据中央 2×2 金阵（单位或建筑）的队伍，全军每 **5 秒 +2 生命** | `updateTerrain()` |

王座只出现在 `throne` 地图中央；其余地图各有至少一块高地与灰烬（生成时带兜底，防止被水/沼泽占满）。

### 表现

- 高地：地块提亮 + 左上高光、右下投影，呈台阶感
- 沼泽：`paintMap` 的泥色底 + 每帧上浮的气泡
- 灰烬：焦黑底 + 暗红斑块 + 上升的余烬颗粒
- 王座：金色描边 + 脉动光环
- 选中单位后悬停特殊地形，光标旁显示「高地：远程射程 +1」等标签

### 寻路兼容

`walkBlocked()` 只把 `water` 视为障碍，沼泽/高地/灰烬/王座都可通行，减速只作用于移动速度。实测：沼泽内单位可正常走出，5 张地图 300 秒模拟均无寻路卡死。

### 调试钩子

`IronCrown.walkBlocked(tx,ty,r)`、`IronCrown.terrainAt(x,y)` 供自动化验证。

## v1.8.1 盟友协同：观战判定 + 共享视野 + 求援标记

### 观战（2v2 阵亡判定修正）

| 情况 | 结果 |
| --- | --- |
| 玩家主堡被拆、盟友仍有基地 | 转入 `spectating`，镜头自动跟随盟友，世界继续模拟 |
| 观战中盟友把敌人拆光 | 结算为**胜利** |
| 观战中盟友也被拆光 | 结算为**失败** |
| 没有盟友时玩家主堡被拆 | 立即判负（不变） |

观战期间玩家无法下指令，镜头锁定最近的盟友基地/部队，目标阵亡会自动切换。

### 共享视野

`playerVisionSources()` 收集**所有非敌方**（玩家 + 盟友）单位与建筑，因此迷雾天然按友方队伍合并：盟友侦察到的区域玩家同样点亮，反之亦然。

### 求援标记

- 快捷键 `Y`（或顶部旗帜按钮），在光标处打一个存活 25 秒的标记
- 冷却 12 秒；无盟友时提示「本局没有盟友」
- 盟友响应条件：**当前不在苦战**（有攻击目标的盟友单位 ≤1）且**闲置兵力 ≥3**
- 响应时派出最多 4 名离标记最近的闲置单位执行 `attackMove`，并提示「盟军回应求援」
- 主地图与小地图都会绘制脉动的求援圈

### 零误伤

`isFriendlyTeam()` 在溅射与超武结算里统一生效：

| 施法者 | 目标 | 结果 |
| --- | --- | --- |
| 玩家超武 / 投石车 | 盟友单位 | 不受伤（实测 140 → 140） |
| 盟友超武 | 玩家单位 | 不受伤（实测 140 → 140） |
| 玩家超武 | 敌方单位 | 正常受伤（140 → -40） |

### 调试钩子

- `IronCrown.kill(unit|building)`：走真实死亡规则（观战/队伍胜负）
- `IronCrown.spectate()` / `IronCrown.superAt(key,x,y,team)` / `IronCrown.requestSupport()`

## v1.8.0 遭遇战：阵营分配槽位表 + 多出生点 + 小地图分队伍配色

### 槽位表（遭遇战设置）

4 个槽位，每个三个下拉框：**控制方**（玩家 / 电脑 / 空）、**阵营**（赤蔷薇 / 青杉 / 黑鸦）、**队伍编号**（1–4）。
预设按钮一键填表：`1v1`、`1v2`、`2v2`。

| 规则 | 行为 |
| --- | --- |
| 至少 1 个玩家槽位 | 否则开局按钮被拦截 |
| 至少 2 个不同队伍编号 | 否则拦截（不能全员一队） |
| 空槽位 | `team` 强制为 `null`（切换控制方的瞬间就置空） |
| 敌对电脑 | 最多 2 个（对应 `AIPlayer` 的 primary + second） |
| 己方电脑盟友 | 最多 1 个 |

校验发生在 `resetWorld()` **之前**——不合格的配置不会毁掉当前战场，只弹提示。

### 多出生点

2 个基地（默认 1v1）仍走原来的手工布局：玩家西南、黑鸦从 `ENEMY_SITES` 随机。
3–4 个基地时启用 `SKIRMISH_SPAWNS` 四个对称点（SW / NE / NW / SE），并为缺矿的基地补齐近矿（每个基地至少 2 处 9 格内矿点），避免出生位置直接决定经济。

### 队伍与配色

| 对象 | 颜色 |
| --- | --- |
| 己方队伍（玩家 + 同队盟友） | 亮绿色（单位 `#c8ffb2`） |
| 敌方队伍 1 | 红色（`#ff8a72`） |
| 敌方队伍 2 | 紫色（`#b98cff`） |
| 其他 | 琥珀色 |

单位与建筑带 `teamId`（队伍编号），小地图按 `teamId` 上色，同队同色。

### 波次与胜负

- **共享兵池**：同队有两个 AI 时，波次规模按基础值的 **1.5×** 计算（`hostileAICount() > 1 ? 1.5 : 1`），不是各自翻倍。
- **胜利**：所有敌对队伍的主堡（或基地车）都被清除才算赢——`enemyHasBase()` 检查全部 `ENEMY` 基地。
- **失败**：玩家自己的主堡 / 基地车被打掉立即判负，**即使盟友仍在**（写死，不做观战）。

### 调试钩子

- `?slots=player,rose,1;ai,raven,2;ai,raven,2;empty,raven,` 直接写入名册再开局
- `?reveal=1` 关闭迷雾（自动化验色 / 观战用）

> 1v1 与战役完全不受影响：AI 时间线基线 `0 / 10 / 55 / 91 / 182 / 187` 逐项不变。

### 手机端修复（详见测试报告）

| 问题 | 根因 | 修复 |
| --- | --- | --- |
| 触屏点选/下令全失效 | `pointerup` 早于 `touchend`，`onPointerUp` 抢先把 `S.panning` 清空，`onTouchEnd` 判定后直接 return | 指针处理器遇 `pointerType === 'touch'` 立即返回，触摸全权交给 `onTouchStart/Move/End` |
| 相机居中错位、基地半个在屏外 | `viewCenter()`/`panBounds()` 只按「右侧栏」算，触屏布局把侧栏移到底部，390px 宽屏中心算成 `x = -2` | `panBounds()` 判断侧栏停靠边（`r.top > VH/2` 为底部），`viewCenter()` 取可视区中心 |
| 点按无法放置建筑 | 放置格只在 `onPointerMove` 更新，而它对 touch 直接 return，`S.placing` 恒为 `(0,0,invalid)` | `onTouchEnd` 的放置分支先 `screenToWorld` + `canPlace` 再 `placeBuilding()` |

### 打包修复：压缩包解压为空

`tools/package.ps1` 原先用 `tar -a -c -f` 压缩，产物每个条目都带 `./` 前缀（`./IronCrown.exe`）。Windows 资源管理器的解压引擎（Shell.Application）读到这种 zip 会**显示 0 项、解出 0 个文件**——即「解压为空」。

改为 `.NET ZipFile::CreateFromDirectory` 后：根目录 19 项、解出 95 个文件、`IronCrown.exe` 就位，`Expand-Archive` 与资源管理器两条路径均验证通过。

### 其他

- GitHub Pages 序章「进入游戏」改为指向 `game.html`（`build-pages.ps1` 补上裸链接改写，不再自指）
- 全站补 `<link rel="icon" href="iron-crown.ico">`，消除每次加载的 `/favicon.ico` 404



## v1.4.10 建造过程可见

| 项 | 说明 |
| --- | --- |
| 放置后进入施工 | 建筑放下不再是「瞬间落成」，而是 `constructed=false` 从 0 长到 1；施工期间**不能出兵、不能射击、不产金、不加人口、不能驻军**（这些判断原本就判 `constructed !== false`） |

## v1.6.0 民心 / 信仰系统

对应红警的「电厂」：军事建筑吃民心，圣泉与大教堂供民心；供给不足时**只会变慢，不会停摆**。

### 收支

| 建筑 | 产出 | 消耗 |
| --- | --- | --- |
| 主堡 | +2 | — |
| 圣泉 | +4 | — |
| 大教堂 | +8 | — |
| 箭塔 | — | 2 |
| 弩炮塔 | — | 3 |
| 兵营 | — | 2 |
| 车厂 | — | 3 |
| 天火祭坛 / 雷霆尖塔 / 瘟疫之井 | — | 5 |
| 农舍 / 市场 / 磨坊 / 铁匠铺 / 瞭望塔 / 城墙 / 军械库 / 战鼓台 | 0 | 0 |

`民心比 = clamp(产出 / max(消耗, 1), 0, 1)`，只在**已完工**的建筑上统计。

### 衰减（线性，不会一刀切停摆）

| 系统 | 系数 | 民心比 0 时 |
| --- | --- | --- |
| 箭塔 / 弩炮塔射速 | `0.5 + 0.5 × ratio` | 50% |
| 兵营 / 车厂训练速度 | `0.8 + 0.2 × ratio` | 80% |
| 超武冷却速度 | `0.7 + 0.3 × ratio` | 70% |

### UI（机制能不能活，全靠这几处）

- 顶栏金币旁新增民心条：`产出/消耗`，绿（满速）/ 黄（≥0.7）/ 红并闪烁（<0.7）；
- 悬停显示：`军事建筑消耗 6，圣泉与大教堂提供 2，缺口 4 —— 箭塔射速 67%、训练 87%、超武冷却 80%`；
- 选中箭塔/弩炮塔显示「射速 67%（民心不足）」，兵营/车厂显示「训练速度 87%」；
- 建造卡片上，若造下去会让民心比跌破 1，右下角出现红色 `!` 并带说明。

### AI

敌方民心缺口 > 5 时优先补圣泉（`tryBuildEnemyFountain()`），再考虑兵营/工坊。

### 实测

| 场景 | 产出/消耗 | 民心比 | 射速 / 训练 / 超武 |
| --- | --- | --- | --- |
| 3 箭塔 | 2 / 6 | 0.333 | 66.7% / 86.7% / 80% |
| 3 箭塔 + 1 圣泉 | 6 / 6 | 1.0 | 100% / 100% / 100% |
| 3 圣泉 | 14 / 0 | 1.0 | 100% / 100% / 100% |

AI 实测（默认 1v1、300 秒）：`aiTimes.fountain = 187s`，出现在超武建筑（182s）之后——正是超武 +5 消耗把缺口推过 5 触发补圣泉。


## v1.6.1 战术单位：狂信徒 + 密探

### 狂信徒（黑鸦专属）

| 属性 | 值 |
| --- | --- |
| 造价 / 人口 | 40 金 / 1 |
| 生命 / 移速 | 50 / 2.2 |
| 攻击 | 无普攻 |

- 右键敌方单位或建筑 → 冲过去，进入 **1 格** 内自动点燃引线；
- **引线 0.5 秒**：期间被击杀则**不会爆炸**（可打断）；
- 爆炸半径 1.5 格：对单位 **80**、对建筑 **30**（减半，防止变成拆家最优解）；
- 选中后按 **D** 原地引爆（同样 0.5 秒引线）；
- AI 不生产狂信徒；但 AI 单位在 2 格内发现敌方狂信徒时，分离推力 **×3**（尝试散开）。

**数值偏差说明**：原规格写「对单位 60」，但弓手生命是 **78**，60 点伤害永远杀不死一个弓手，与你写的验收标准（「弓手死 2–3 个」）矛盾。本实现取 **80**：实测 3 个弓手全灭、主堡掉 30 血（2600 → 2570）。若要严格回到 60，改一处数字即可，但那条验收就不可能通过。


### 密探（通用）

| 属性 | 值 |
| --- | --- |
| 造价 / 人口 | 100 金 / 1 |
| 生命 / 移速 | 60 / 2.0 |
| 攻击 | 无 |

- 走到敌方建筑 **2 格内**，右键该建筑 → 潜入偷金币；
- **被识破条件**：该建筑 2 格内有敌方非农民单位，或 3 格内有敌方箭塔/弩炮塔 → 密探当场死亡；
- 成功：密探消失（不返回），按目标建筑给钱：市场/磨坊 **150**、主堡（金库）**120**、其它建筑 **80**；
- 兵营/车厂/超武建筑的「偷科技 / 干扰超武」按规格留到第二版；
- AI 不生产密探；密探靠近敌方建筑时，该建筑上方显示「眼睛」图标。

**AI 没有经济怎么办**：`S.gold` 是玩家唯一的钱包，AI 建筑是免费瞬建，所以「敌方 −150」没有对应变量。本实现新增 `S.enemyChest`（敌方军资，初始 600、每秒 +1.2、上限 900）作为可被偷的对象：偷取时玩家等额加钱、`chest` 扣除；若扣完低于 50，敌方下次训练额外 +3 秒（「补给中断」）。这是为了让密探在遭遇战里真的有用，不代表 AI 有真实经济。

**作战要点**：AI 不造市场/磨坊，所以遭遇战里最稳的偷法是**主堡（+120）**，或趁 AI 部队外出时偷其它建筑（+80）。

实测：`?spytest=1`（玩家基地旁放一座无人看守的敌方磨坊）→ 金币 2000 → **2150**、敌方军资 600 → **450**、密探消失；`?spytest=fail`（旁边放一个敌方弓手）→ 金币与军资不变、密探阵亡。

## 玩法概览

开局只有主堡、三名农民和少量部队。占矿、造农舍扩人口、建兵营出兵，顶住一波波黑鸦进攻；
五章战役逐关解锁新的兵种与工事，最终迎战黑鸦之王。

### 战役（五章）

| 章节 | 敌方特性 | 数值倾向 | 通关解锁 |
| --- | --- | --- | --- |
| 边境劫掠 | 掠夺成性 | 甲胄单薄，首波更晚 | 长戟兵 |
| 铁鸦重甲 | 重甲 | 生命 +35%、伤害 +5%、移速 −10% | 战地祭司 |
| 群鸦奔袭 | 疾行 | 移速 +25%，出兵更快 | 军械库 |
| 瘟疫投石 | 淬毒 | 伤害 +30%、生命 +20%，攻城队登场 | 弩炮塔 |
| 黑鸦之王 | 王者之怒 | 生命 +55%、伤害 +45%，最终决战 | — |

战役起始资金固定为 **1200**，主界面不提供调整入口；只有遭遇战可以自定义起始金钱。

每章开战前会先播放一张剧情卡（章节标题 + 两段叙事 + 作战目标），胜利后追加该章尾声；打通终章会显示完整结局。剧情卡可点「跳过剧情」直接开打，重开同一章不会重复播放。

### 遭遇战

从标题页「遭遇战」标签进入，与黑鸦 AI 自由对局：

| 选项 | 可选值 | 说明 |
| --- | --- | --- |
| 起始金钱 | 1000 / 2000 / 4000 / 8000 | 双方同额，默认 2000 |
| 初始步兵 | 0 / 2 / 4 / 6 / 8 | 双方相同，随机长矛 / 剑士 / 弓手 / 重弩 |
| 超级武器 | 开 / 关 | 关闭后双方都无法建造 T3 超武建筑，也没有超武卡片 |
| 难度 | 侍从 / 骑士 / 国王 | 影响 AI 出兵速度、波次规模与上限 |
| 青杉盟军 | 开 / 关 | 可选 AI 队友 |

遭遇战双方开局就有一座完工主堡，全部军备默认解锁，并启用波次攻势（战役保持原有节奏）。摧毁对方主堡即胜。

### 奖励箱

对局中每 45–70 秒在空地刷新一个宝箱（场上最多 3 个，75 秒未拾取会消失），玩家单位走近即自动拾取：

| 宝箱 | 效果 |
| --- | --- |
| 金币箱 | +200~400 金币 |
| 援军箱 | 现场召唤 2~3 名已解锁步兵 |
| 补给箱 | 全军回复 25% 生命 |
| 超武箱 | 超级武器冷却清零；未选超武或超武关闭时折算 300 金币 |

宝箱会显示在小地图上（仅视野内）。**双方都能拾取**：黑鸦的闲置单位在视野内发现宝箱会主动前往，抢到后治疗周围部队；箱子因此变成地图上的争夺点。

## 技术实现

- `web/game.js` 单文件约 4,500 行，无框架、无构建步骤、无任何 CDN 依赖。
- 菱形等距：瓦片 64 × 32，地图 56 × 56，Canvas 2D 逐帧重绘 + 深度排序。
- 战争迷雾分「实时可见」与「记忆残影」两层，瞭望塔提供全场雷达。
- 敌方 AI 为波次推进 + 建造决策；可选友军 AI 会自主造兵、支援与共享视野。
- 寻路：直线可达时直接走；被建筑或水面挡住时用 56×56 网格 A*（8 邻接、禁穿角、拐点拉直），最后的推挤与群体分离只处理贴身碰撞；路径按每帧预算错峰计算。
- 音效由 WebAudio 实时合成；单位应答语音为 12 段离线 TTS（4 类指令 × 3 变体）。
- Electron 45.3.4 + `@electron/packager` 打包，主进程开启 `contextIsolation` / `sandbox`。

## 重新打包

```powershell
npm install
npm run package                      # 输出 dist\IronCrown-win32-x64\
npm run dist                         # 额外压出 dist\IronCrown-1.1.0-win64.zip
```

## 发布到 GitHub（无需 git）

本机没有 git / gh 也能发版：`tools/publish/` 直接走 GitHub REST API（blob → tree → commit → ref → Release）。

1. `powershell -File tools\publish\start-login.ps1` —— 打印一次性设备码，浏览器授权后 token 落到 `%USERPROFILE%\.ironcrown-secrets\token.json`
2. `powershell -File tools\publish\poller.ps1` —— 轮询直到输出 `AUTH_OK`（可放后台）
3. `powershell -File tools\publish\push.ps1 -SkipRelease` —— 只推代码
4. `npm run dist` 之后再跑 `powershell -File tools\publish\push.ps1` —— 顺带把 zip 传成 Release 附件

脚本会自动跳过 `dist/`、`node_modules/`、`.git/`、`*.zip` 与截图；仓库描述、提交信息、Release 文案在 `tools/publish/meta.json`（UTF-8），支持 `{SIZE_MB}` `{SHA256}` `{LOGIN}` `{REPO}` 占位符。
