# 铁与王冠 · AIPlayer 对比基线（v1.4.9）

> 本文件是 AIPlayer 多实例化（v1.5.0）重构前后的对比锚点。以后每次对比报告**追加在本文件末尾**，形成基线演进链。

## 1. 采集条件

| 项 | 值 |
| --- | --- |
| 版本 | v1.4.9（warp cap 已从 4000 步修正为 30000 步） |
| 命令 | `index.html?autostart=1&mode=skirmish&map=border&debug=1&warp=300` |
| 额外钩子 | 无（不带 `give / dense / aifaction / diff`） |
| 地图 / 难度 | border / 默认 |
| 模拟时长 | 300 秒（6000 步 × 0.05s，真实推进，非跳时间） |
| 结束状态 | 两次均在约 290 秒前被 AI 摧毁主堡（`mode=ended`），有效区间 0–291 秒 |
| warp 是否渲染 | 否（`update()` 内 `render/ctx` 命中数为 0），故 `stuckTeleports`、`sepMs` 为纯逻辑层数值 |

**逐点偏差**：0–80 秒全为 0；90–190 秒区间偏差 1–2（集中在 AI 训练出的随机兵种数量）；190 秒后两次都到 18 饱和，偏差 0。

**结论：容差 = ±2**（实测最大偏差 2，未超过 4，故不启用斜率兜底）。

## 4. stuckTeleports / stuckPeak（AIPlayer 对比锚点）

| 指标 | 第 1 次 | 第 2 次 | 说明 |
| --- | --- | --- | --- |
| `stuckTeleports`（累计保命传送） | 137 | 113 | 默认配置下 AI 自己造建筑导致的夹缝卡位 |
| `stuckPeak`（同时卡住峰值） | 9 | 6 | 峰值高说明有一批单位同时卡住 |

**判读规则**（以后对比用）：
- 次数高 + 峰值低 → 推挤方向问题（反复卡、每次一两个）；
- 次数高 + 峰值高 → 建筑夹缝或寻路网格问题（一批同时卡）。

**与「密集场景 61 次」的区别**：61 次是玩家在主堡周围堆 6 农舍 + 4 箭塔的**人为密集场景**，只作为「建筑夹缝根因」的参考值；本文件的 137/113 才是 **AIPlayer 对比锚点**，两者不可混用。

- 6000 步 300 秒模拟耗时约 **2.5–3.2 秒**，无单一热点段；两次的「最慢段」不同（第 2 段 vs 第 4 段），判断为 GC/系统抖动，不是固定热点。
- 若以后出现「各段均匀显著变慢」，先查单步成本（例如 AI 训练循环里的全量 `S.units.filter`），再谈 AIPlayer。

## 6. AIPlayer 对比协议（执行清单）

1. **同图同布局**：都用 `?map=border&warp=300`，不额外 `give`；
2. **两端都不带** `?give / ?dense / ?aifaction`；
3. 判据分层：

| 判据 | 类型 | 阈值 |
| --- | --- | --- |
| `aiTimes`（兵营/工坊/首波/超武） | 硬断言 | 误差 ≤1 秒 |
| 首波时间、首波兵力数 | 硬断言 | 完全一致（`seed()` 确定性） |
| `enemyUnits` 前 60 秒 | 容差 | **±2**（实测值） |
| `enemyUnits` 60 秒后 | 趋势 | 不逐点比对，看同量级增长 |
| `enemyTypes` | 只记录 | 训练含 `Math.random`，不判等 |
| `stuckTeleports` + `stuckPeak` | 量级比对 | 差异显著 → 先查推挤/传送，别归因重构 |

4. **兜底规则**：若以后实测容差 >4，改用「前 60 秒 `enemyUnits` 线性回归斜率，新旧差异 ≤15%」；
5. 对比 `sepMs` 时关闭调试浮层（`?dbg=0`），避免 DOM 写入污染计时。
